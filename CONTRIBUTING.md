# Contributing

Thank you for considering a contribution to PolySparQ++.

## Before opening a change

- Open an issue first for a large feature, strategy change, or API redesign.
- Keep pull requests focused and explain user impact, safety impact, and how you checked the change.
- Do not include credentials, wallet keys, personal trading records, database dumps, private infrastructure details, or generated build files.
- Do not include investment-performance claims unless they are reproducible, dated, and clearly identify the data and test method.

## Development checks

For C++ changes, build with CMake and run relevant tests. For Python changes, run the affected module checks. For mobile changes, run `npm run typecheck` from `mobile/` and describe any native build checks performed. Never run tests against a production database or wallet.
